Everything one turn of the loop needs.

An agent needs more than one exec call. It stages files, clones a repo, keeps a process alive, reads why a run stopped and starts the next attempt from clean. Each of those is one SDK call.

Why a run ended

Every exec result can carry a stop_reason, so the agent tells a hung test from a full output buffer from a sandbox that was reset under it.

stop_reasonwhat happened
timeoutThe command ran past timeout_s (default 60 s, up to 3600 s).
output_limitOutput passed the size cap and the command was stopped.
sandbox_stoppedThe sandbox stopped during the run, for example after a limit overrun on the gvisor or microvm tier.
killedThe command was killed.
sandbox_deletedThe sandbox was deleted while the command ran.
sandbox_resetThe sandbox was reset while the command ran.

The Python SDK resends 429, 503 and dropped connections on requests that are safe to repeat; create_sandbox(idempotency_key=...) makes a retried create return the first sandbox. Every 409 carries a machine-readable details.reason.

Hosted beta: the API and the sandboxes run on our evaluation instance, outside your network.

Assume the code is hostile. Choose the boundary per sandbox.

Nobody on your team wrote or reviewed what the model generated. Pick the isolation tier on each create with one field, isolation; GET /v1/isolation lists the tiers a server offers.

container
your codehardened container · runchost kernel, shared

Namespaces, cgroups, a seccomp profile and reduced capabilities. Fastest for spawn-heavy and small-file work.

Shares the host kernel. With an egress allowlist on this tier, DNS is a side channel.

gvisorbeta default
your codegVisor · user-space kernelhost kernel, filtered surface

A kernel in user space handles system calls, so the host kernel sees a small, filtered surface.

A user-space kernel, not a hardware boundary. Spawn-heavy and small-file work runs about 3× to 9× slower; large writes count toward memory; a limit overrun can stop the whole sandbox.

microvm
your codeKata Containers · own guest kernelKVM

Each sandbox gets its own guest kernel in a lightweight VM, behind the same Docker driver and the same API.

Needs KVM; a create takes seconds, not milliseconds. On the hosted beta it runs on the evaluation instance’s nested KVM.

privilege
All capabilities dropped except seven, no-new-privileges; host seccomp on the container tier
resources
pids_limit (bounds the process count on the container tier only), CPU, memory and disk caps; disk size enforced per sandbox on all three beta tiers
network
Per sandbox: open, an allowlist through the egress proxy, or block_network with no network and no DNS. The metadata address is blocked.
secrets
SANDFORT_ variables never reach a sandbox
docker
The socket is never mounted into a sandbox
host

We do not claim stronger isolation than VM-based sandbox products. These controls reduce the risk of an escape; they do not remove it.

A sandbox platform your security team can audit.

Audit, access control, quotas and usage ship in the same package, and are written in the same transaction as the state change they describe.

Tamper-evident audit chain

A per-organization hash chain over every mutating call; denied requests are recorded as request.denied. Export it as NDJSON with hashes and verify it over REST with audit:read. sandfort audit verify-head checks an export file against the signed head and exits 3 on a break, so cron or CI can run it. Roles and scoped keys

Roles admin, developer, viewer map to scopes. Admins change roles and remove members through PATCH and DELETE on /v1/org/members; the last admin cannot be removed. API keys are stored as salted hashes and shown once; a key cannot grant scopes it does not hold.

Keys limited by label

A key limited to up to 8 label pairs sees only matching sandboxes; everything else answers 404. One key per team or per customer.

Snapshots, volumes, usage and audit stay organization-wide.

OIDC SSO and SCIM

OIDC identity tokens are exchanged for short-lived sessions. SCIM 2.0 provisions users when it is enabled in configuration; it is off by default.

SSO signs in to one configured organization. SCIM covers Users only: no groups, bulk or etag.

Quotas, usage, webhooks

Per-organization quotas, reserved again on start so stop and start cannot bypass the cap. Usage grouped by sandbox or label for chargeback. Signed webhooks with redelivery, https only in prod.

Usage meters allocated resources; it is not billing.

SSO, SCIM and per-organization quotas are self-hosted configuration; the hosted beta uses API keys, and there are no certifications such as SOC 2 or ISO 27001.

From one Docker host to your cluster.

The same package runs as one process on a laptop or as separate api and worker roles on your nodes.

One process, local Dockerone host

A Python process and the Docker daemon. SQLite for development, Postgres for production. The container and gvisor tiers need no KVM.

Per-sandbox disk limits need XFS project quota; Docker Desktop does not enforce them.

A dedicated sandbox nodeone-node kubernetes kit

deploy/k8s/ runs one pod with API, workers and preview proxy on a node labelled for sandboxes. deploy/node-setup.sh prepares Docker storage, gVisor and optional Kata.

Replicas fixed at 1. No published container image yet: build deploy/Dockerfile.

Placement and cross-node routingmulti-node

A node registry places sandboxes; a request that reaches the wrong node is forwarded to the node that owns the sandbox.

Needs jobs mode, a shared database and a private network: the hop is plain HTTP with an HMAC route token. Jobs mode refuses volume mounts and egress allowlists on create and has no reset.

What it does not do yet.

Better you read it here than find it in week two of an evaluation.

  • Every tier is a trade-off.container shares the host kernel; gvisor is not a hardware boundary; microvm needs KVM and starts in seconds.
  • Docker socket on sandbox nodes.The server mounts it, and it grants control of the node. Use dedicated nodes.
  • A sandbox lives on one node.Multi-node needs jobs mode, a shared database and a private network.
  • SSO into one organization; SCIM Users only. There are no SCIM groups, bulk operations or etags.
  • No built-in TLS; /metrics is unauthenticated.Put both behind your own proxy and network policy.
  • The console and web terminal load their terminal library from a public CDN.Self-host it if nothing may load from outside.
  • Version 0.1.0, beta.Releases are git tags v0.1.0-beta.N with signed wheels and a signed checksum file; see how releases are built and verified. Built from October 2026.
  • No production references and no certifications yet.The design partners are the first users.

Questions we get first.

Doesn’t a hosted beta contradict “the code stays on your hosts”?

The beta is for evaluation only: no production secrets and no sensitive data. In production Sandfort runs self-hosted on your infrastructure, and that stays the default.

Is it open source?

It is source-available under FSL-1.1-Apache-2.0: self-hosting and changes are allowed, running a competing service is not. Each version becomes Apache-2.0 two years after release.

What does it cost?

There are no prices yet. Pilots for a small number of design partners are free; the commercial model is decided after the pilots.

Which languages can the agent run?

code_run takes Python, JavaScript, TypeScript and bash; process_exec runs anything installed in the image. Build images from a declarative spec, cached by spec hash.

How were the numbers on this page measured?

Tests: 18123 collected by pytest --collect-only -q on 2026-11-27. It is a collected count, not a pass count, and that run did not execute the tests. HTTP operations: counted in the exported OpenAPI spec on 2026-11-27, the same 91 operations as on 2026-11-22, including /healthz and /readyz, excluding the PTY WebSocket, /metrics, the preview proxy and the web terminal. Gates 1–5 ran on real Docker; gates 6–10 ran locally on 2026-11-01 and 2026-11-02; The first fully green CI run was on 2026-11-03.

Latency: examples/benchmark.py, 20 creates waiting for started and 50 short commands in one sandbox, alpine:3.20 pre-pulled.
